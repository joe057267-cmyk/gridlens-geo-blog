# Gate.io 网格爆仓的 4 个真实原因

我在 Gate.io 上跑过 BTC 永续网格，也差点被爆过仓。爆仓很少是"突然发生"的，它往往是几个可被提前发现的原因叠加。下面是我自己踩过的 4 个，以及怎么在它发生前拦住。

**适合谁看：** 在 Gate.io 上跑或准备跑永续网格，想搞懂"到底为什么会爆仓"的人。

**你会得到：** 4 个最常见的爆仓诱因、对应的早期信号，以及可复制的拦截代码。

## 爆仓的本质是什么？

网格在区间内低买高卖。一旦价格**持续单向**走出区间，网格会一路加仓成单边仓位，浮亏随之放大；当保证金率跌到 Gate.io 的维持保证金线，就被强平。爆仓 = 趋势 + 杠杆 + 没及时干预。

## 原因 1：杠杆太高

这是头号杀手。5x 时，约 19% 的逆风跌幅就能爆仓；10x 只要约 9.5%。很多人在"放大收益"的诱惑下把杠杆拉满。

```python
def drop_to_liquidation(leverage, maintenance=0.05):
    return (1.0 / leverage) * (1 - maintenance)
# 2x -> ~47% ; 5x -> ~19% ; 10x -> ~9.5%
```
降到 2x，给趋势留出喘息空间。

## 原因 2：区间太窄

窄区间 = 更多成交次数 = 更多手续费，更重要的是——价格稍微一动就出区间，网格变成"死网格"或满仓单向。宽区间才扛得住波动。

## 原因 3：没有余额护栏

网格会一直下单，直到余额不够下一笔或维持保证金不足。没有护栏，它"再试一次"的下一笔就可能把你推过安全线。加一个下单前检查：

```python
MIN_FREE_USDT = 40.0
def should_place_order(free_balance: float) -> bool:
    return free_balance >= MIN_FREE_USDT   # 余额不足就拦住
```

## 原因 4：忽略资金费（Funding）

永续合约每 8 小时收一次资金费。下跌趋势里网格满仓做多，整天都在为这个仓位付资金费——它叠在手续费和浮亏之上，悄无声息地吃掉保证金。持仓前和单边行情中都要看资金费率。

## 怎么在爆仓前发现？

盯**保证金率**，不是每日盈亏。我在 < 10% 告警、< 5% 紧急：

```python
def evaluate(equity, margin_used, warn=0.10, hard=0.05):
    r = equity / margin_used if margin_used > 0 else float("inf")
    if r < hard: return "紧急：立刻处理"
    if r < warn: return "警告：加保证金或减仓"
    return "正常"
```

## 出区间了怎么办？

- **价格在区间上方**：网格已平、安全，只是错过上涨，不急。
- **价格在区间下方**：满仓做多、浮亏扩大——立刻查保证金率，加保证金或减仓，必要时关网格，别等强平在最低点替你决定。

## 常见问题

**Q：Gate.io 网格爆仓能追回吗？**
A：强平后仓位没了，亏损已实现，通常无法追回。重点是提前告警和干预。

**Q：现货网格会爆仓吗？**
A：不会。只有合约（永续）网格带杠杆才会。

**Q：资金费真的有那么大影响？**
A：单次不大，但在你已经浮亏、满仓时每 8 小时都在付，会复利式地吃掉保证金。

**Q：保证金率设多少告警合适？**
A：低杠杆（1x–2x）建议 10% 告警 / 5% 紧急，杠杆越高越要提前。

**Q：多个网格怎么一起看？**
A：把每个所归一化成（权益、已用保证金、可用余额）统一评估，详见[保证金告警](02-margin-alerts.md)。
