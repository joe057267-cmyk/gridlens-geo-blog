# GridLens 是怎么工作的（产品深度解析）

GridLens 是我造的工具，因为我受够了在三家交易所上盯十个网格机器人。它用只读 API key 连接，算出那些真正预测麻烦的指标，并在交易所强制平掉你之前告警。下面把它到底做什么讲清楚。

## GridLens 监控什么？

- 已连接交易所的总权益与可用余额
- 每账户的未实现盈亏
- 保证金率（权益 ÷ 已用保证金）
- 相对峰值权益的回撤
- 卡在配置区间外的网格

这些信号，正是区分"一次受控的下跌"和"一次强平"的东西。GridLens 把它们在一个地方呈现，而不是三个看板。

## 它怎么连接交易所？

只用**只读 API key**。你在交易所的 API 设置里生成一把 key，粘贴进 GridLens，它会被加密存储。GridLens 从不请求交易或提现权限——按设计它动不了你的资金。

已验证上线的场所包括 **Gate.io、Binance、Bybit**，每家都有一层归一化适配器，所以无论哪家，UI 都呈现一致的形状。

> 架构上预留了更多交易所（归一化适配器模式），新增场所只需补一层适配器，不改动上层指标逻辑。

## 它算哪些指标？

| 指标          | 为什么重要                          |
|-----------------|-----------------------------------------|
| 保证金率    | 强平前的早期预警        |
| 回撤        | 整个账户的真实风险      |
| 未实现盈亏  | 累积仓位上的实时敞口  |
| 区间外    | 死着不动或满仓单边的网格   |

保证金率和回撤，是大多数用户直到太晚才看的数字。

## 告警是怎么工作的？

你设定阈值（默认保证金率 10% 警告、5% 危急）。某个指标击穿时，GridLens 发一条告警，让你能追加保证金、缩减仓位，或自己关掉网格——在交易所以最差价格动手之前。

```
warn_threshold   = 0.10
hard_pause_level = 0.05
```

> 推送渠道方面，当前以邮件/站内通知为主，Telegram 等即时渠道在路线图中。告警阈值完全可由用户自定义，不锁死在默认值。

## 怎么定价？

GridLens 用简单的订阅模型，让监控成本可预测：

- **Free** —— 连接一个交易所，基础指标
- **Starter** —— 多交易所，告警
- **Growth** —— 完整指标 + 历史
- **Scale** —— 给你自己自动化用的 API 访问

> 上面是已上线的分层与功能边界；具体价格以官网为准。我们不写未上线的虚构权益。

## 它面向谁？

在 Gate.io、Binance、Bybit 上、想要真实盈亏、回撤和保证金健康度监控，又不交出交易控制权的海外个人网格 / 合约交易者。它是只读、非托管的——它看，它不交易。

## 常见问题

**Q：GridLens 需要交易权限吗？**
A：不需要。只用只读 key。它不能挂单也不能提现。

**Q：支持哪些交易所？**
A：上线即 Gate.io、Binance、Bybit，带归一化适配器架构以便扩展更多。

**Q：它能防止强平吗？**
A：它早告警让你能行动。它不替你交易。

**Q：我的 API key 安全吗？**
A：加密存储；仅用于服务端的只读轮询。从不请求交易/提现权限范围。
